| 項目 | 內容 |

---

## 1. 目的

確保個案從**建立 → 分派/跟進 → 完結申請 → 審核 → 關閉/重開**的全生命週期邏輯正確，並確保附件的**上傳 / 下載 / 刪除**穩定可用。本計畫特別鎖定本次修正的「**附件刪除（含斜線 caseId 的 `%2F` 路由匹配回歸）**」以及**附件稽核日誌**的正確性。

---

## 2. 範圍

### 2.1 包含（In Scope）

| 類別 | 項目 |
| --- | --- |
| 個案 CRUD | 手動建案（欄位校驗 / 屋苑範圍）、列表（篩選 / 分頁 / 屋苑隔離）、詳情（個案 / 時間軸 / `allowedActions`） |
| 生命週期狀態機 | `assign` / `reassign` / `start` / `waiting` / `resume` / `note` / `priority` / `resolve-request` / `approve` / `reject` / `reopen` 的合法與非法轉換 |
| 附件管理 | 上傳（成功 / 副檔名 / 大小 / 空檔 / 非 buffer）、列表（經詳情返回）、下載、刪除（成功＋稽核＋實體清理） |
| 回歸重點 | 含 `/` 的 caseId 以 URL 編碼 `%2F` 的 `DELETE` 附件仍可匹配；`RESOLVED` / `CLOSED` 狀態阻擋上傳與刪除 |

### 2.2 排除（Out of Scope — AI 模組）

本計畫**不含**任何 AI 能力測試。下列端點 / 服務明確排除，避免後續誤擴充：

- 路由：`/ai-suggestions`、`/ai-suggestions/.../accept|reject|link`、`/ai-suggestions/refresh`、`/ai-assignee-suggestion`、`/ai-draft`、`/ai-draft/.../use`、`/ai-feedback-insight`、`/attachments/ai-insights`、`/attachments/:id/analyze`
- 服務：`services/aiService.js`、`services/aiProvider.js`、`services/aiGenerate.js` 及既有 `test/aiService.test.js`
- 說明：建案時的 AI 影子模式入隊（`enqueueClassify` / `enqueueSimilar`）失敗不影響建案，不在本計畫驗證範圍內（已由 `ai.enabled=false` 預設關閉）。

## 3. 測試策略

採用**雙層覆蓋**，兼顧精準度與路由真實性：

1. **Service 層單元測試**（`caseLifecycle.test.js`、`attachment.test.js`）：直接呼叫 `caseService` 函式，精準驗證狀態機、錯誤碼與資料庫副作用，速度快、易維護。
2. **HTTP 層整合測試**（`attachmentHttp.test.js`）：使用 `supertest` 打真實 Express 路由，覆蓋鑑權（`requireAuth`）、權限（`requirePerm`）、路由匹配與 `%2F` 編碼回歸。

**資料隔離**：每次測試建立全新資料庫（Service 層用 better-sqlite3 `:memory:`；HTTP 層用臨時檔案 DB），並載入 `db/seed.js` + `ensureDefaults`，無跨測試副作用。附件實體檔寫入臨時目錄（`process.env.UPLOAD_DIR`），測試結束清理。

### 6.2 生命週期狀態機（caseLifecycle.test.js）

狀態轉換矩陣（取自 `constants.TRANSITIONS`）：

```
PENDING   → ASSIGNED
ASSIGNED  → ASSIGNED(轉派) / IN_PROGRESS
IN_PROGRESS → ASSIGNED / IN_PROGRESS / WAITING / RESOLVED
WAITING   → ASSIGNED / IN_PROGRESS / WAITING / RESOLVED
RESOLVED  → IN_PROGRESS(駁回) / CLOSED(通過)
CLOSED    → REOPENED
REOPENED  → ASSIGNED / IN_PROGRESS
```

| 用例 ID | 描述 | 預期結果 | 錯誤碼 / HTTP |
| --- | --- | --- | --- |
| LC-06 | `submitResolution → approveResolution → reopenCase` | 流轉 `RESOLVED → CLOSED → REOPENED`；重開標記 `is_second_complaint=1`（SECOND_COMPLAINT） | 200 |
| LC-07 | 完結申請校驗 | 非法 `result` / 缺 `summary` / `UNRESOLVED` 缺原因 | `VALIDATION 1002` |
| LC-08 | 非法轉換 | `approve`（非 RESOLVED）、`reopen`（非 CLOSED）、`submitResolution`（PENDING）、`reject`（非 RESOLVED）、`start`（PENDING） | `STATE_TRANSITION 3002` |
| LC-09 | 審核駁回 | `RESOLVED → IN_PROGRESS`，寫 `RESOLVE_REJECT` 時間軸 | 200 |
| LC-10 | 優先級調整 | `CLOSED` 阻擋；`RESOLVED` 允許；非法優先級拋 `VALIDATION` | `3002` / `1002` |

## 8. 風險與已知限制

- **caseId 含斜線**：真實編號格式為 `公司/業務/屋苑/日期流水`（如 `SMS/SR/CHNG/260928001`）。前端必須以 `encodeURIComponent` 編碼後再組 URL；`DELETE` 路由依賴此編碼方可匹配（本次修正核心）。AH-03 已鎖定此回歸。
- **附件刪除權限**：上傳與刪除皆需 `case:update` 且個案處於 `ACTIONABLE` 狀態（`ASSIGNED` / `IN_PROGRESS` / `WAITING` / `REOPENED`）；`RESOLVED` 與 `CLOSED` 均被阻擋（與優先級調整不同——優先級僅 `CLOSED` 阻擋）。
- **附件預覽**：本系統無獨立 preview 端點，預覽由 `download` 端點（附 `Content-Disposition`）承載，測試以「可成功下載回檔」驗證。
- **AI 模組**：已於本計畫明確排除；若未來新增 AI 測試，請另立文件並避免與本計畫用例混淆。
