## 1. 系統簡介

### 1.1 系統做什麼

QRCode 客戶意見反饋系統讓住戶以手機**掃描屋苑張貼的 QR Code**，即可填寫對管理處／保安／維修等服務的意見。意見會自動成為一宗**個案**，由客服中心與物業管理處人員於**後台**處理、跟進，直至完結關閉；經客戶同意參與者，個案關閉後會收到**匿名滿意度問卷**，統計結果供管理處參考以持續改善服務。

系統分兩大端：

| 端 | 使用者 | 網址 | 說明 |
|---|---|---|---|
| 公用端 | 住戶／公眾 | `http://localhost:5173` | 意見表單、提交成功頁、滿意度問卷（無需登入） |
| 後台 | 管理處及客服人員 | `http://localhost:5173/admin/login` | 個案管理、QR Code 管理、問卷統計、儀表板、系統管理（需登入） |

### 1.2 整體流程

```
① 管理員於後台「QR Code 管理」為各屋苑生成並下載 QR Code（可設定有效日期）
        ↓ 列印並張貼於屋苑當眼位置
② 住戶掃描 QR Code → 開啟該屋苑的「客戶意見反饋」表單
        ↓ 填寫並提交（同意者可勾選接受後續滿意度調查）
③ 系統即時建立個案，產生「個案編號」，住戶於成功頁看到編號
        ↓
④ 客服／管理處人員登入後台：查看、分派、開始處理、跟進、申請完結
        ↓
⑤ 主管／客服審核通過 → 個案關閉（SLA 逾期／接近期限時系統會提醒並升級）
        ↓
⑥ 系統對「同意參與調查」的客戶寄送匿名滿意度問卷連結（14 天內有效）
        ↓
⑦ 客戶填寫問卷 → 後台「問卷統計」與「數據分析儀表板」更新
```

### 1.3 個案編號

個案編號由系統自動產生，格式為：

```
公司代碼 / SR / 屋苑代碼 / 日期 + 當日流水號
```

示例：`CRPM/SR/CWC/260907001`（示意）。編號會顯示於住戶提交成功頁、後台個案列表與詳情，是住戶查詢與你跟進個案的唯一依據。

### 1.4 屋苑清單

屋苑主檔維護於後台「**屋苑**」頁（第 10.5 節），以下為出廠預設的四個屋苑：

| 代碼 | 中文名 | 英文名 | 公司代碼 |
|---|---|---|---|
| CWC | 灣景中心 | Bayview Centre | CRPM |
| YPR | 攸壆路 | Yau Pok Road | PML |
| CHNG | 頌雅苑 | Chung Nga Court | SMS |
| DAHF | 大夫第 | Dai Fu House | SMS |

> 新增屋苑**不需修改程式**：管理員於「屋苑」頁新增後，個案列表／儀表板／問卷統計／用戶管理等屋苑下拉即會出現新屋苑，並可為其生成 QR Code、開設所屬屋苑帳號（操作見第 10.5 節）。屋苑中文／英文名稱或公司代碼修改後，歷史個案等顯示即時跟隨更新（名稱由主檔帶出）。**請勿直接於資料庫刪除屋苑**（既有個案與 QR Code 以主檔參照），亦避免修改已使用的屋苑代碼（代碼會作為個案編號前綴，見 1.3 節）。

## 2. 角色與權限

### 2.1 角色一覽

| 角色代碼 | 角色名稱 | 數據範圍 | 一般負責工作 |
|---|---|---|---|
| ADMIN | 系統管理員 | 全屋苑（ALL） | 系統管理：QR Code 生成／停用、用戶與角色、系統參數、審計 |
| CC_SUPERVISOR | 客服中心主管 | 全屋苑（ALL） | 個案審核、分派、重開、參數查閱、QR／用戶查閱 |
| CC_STAFF | 客服中心人員 | 全屋苑（ALL） | 處理個案：分派、跟進、申請完結、匯出 |
| ESTATE_SUPERVISOR | 物業管理處主管 | 所屬屋苑（ESTATE） | 審核屋苑個案、分派、重開、查閱用戶／角色／審計 |

## 3. 登入與後台介面（快速開始）

### 3.1 登入

1. 瀏覽器開啟後台網址：`http://localhost:5173/admin/login`
2. 輸入**帳號**與**密碼**（兩者皆必填）
3. 按「**登入**」（送出時顯示「登入中…」）
4. 登入成功後自動前往「個案管理」列表

> 登入失敗時，畫面會顯示後端回傳的原因（例如帳號或密碼錯誤、帳號已停用／已鎖定）。輸入錯誤達系統設定次數，帳號會被鎖定，需由管理員解鎖。

（待補截圖：登入頁）

### 3.2 後台介面導覽

登入後的畫面由上而下大致為：

1. **頂列**：左側為系統名稱「個案管理系統」＋副標「QRCode 客戶意見反饋 · 後台」；中間／左方為目前頁面標題；右方顯示你的**姓名**、**通知中心（鈴鐺）** 與 **登出** 圖示。
2. **功能導覽**（ToggleButton 橫排，僅顯示有權限的項目）：**個案 / QR Code / 問卷 / 儀表板 / 參數 / 用戶 / 角色 / 審計 / 屋苑**。
3. **內容區**：隨選擇的功能顯示列表或詳情。

| 導覽項目 | 對應工作 |
|---|---|
| 個案 | 查看與處理意見個案（第 5–6 章） |
| QR Code | 為各屋苑生成／停用 QR Code、設定有效日期（第 7 章） |
| 問卷 | 查看滿意度問卷統計（第 8 章） |
| 儀表板 | 查看 12 項 KPI 與圖表分析（第 9 章） |
| 參數 | 查看／編輯系統參數（第 10.4 節） |
| 用戶 | 管理後台使用者帳號（第 10.1 節） |
| 角色 | 管理角色與權限（第 10.2 節） |
| 審計 | 查閱操作日誌（第 10.3 節） |
| 屋苑 | 維護屋苑主檔（新增／改名／停用）（第 10.5 節） |

### 3.3 通知中心

頂列右側的**鈴鐺**圖示開啟通知中心（未讀時顯示紅色數字徽章，上限 99；每 30 秒自動更新未讀數）。

| 通知類型 | 圖示／顏色 | 例子 |
|---|---|---|
| 提醒（REMINDER） | 橙 | SLA 接近／已逾期提醒 |
| 升級（ESCALATION） | 紅 | 個案逾期升級 |
| 問卷（SURVEY） | 綠 | 問卷已回覆 |
| 個案（CASE） | 藍 | 個案狀態變更等 |
| 系統（SYSTEM） | 灰 | 系統訊息 |

- 點擊某則通知：未讀通知會先標示為已讀；若是**個案**相關通知，會自動跳轉至該個案詳情頁。
- 按「**全部已讀**」可一次清除未讀狀態（只有存在未讀通知時顯示）。
- 面板只顯示最近 20 筆；更早的通知請以「審計」或個案時間軸查閱。

### 3.4 登出

按頂列最右的**登出**圖示，即可結束工作階段並返回登入頁。為保安起見，離開座位時請登出。

## 4. 住戶端操作（公眾）

本章是住戶（一般使用者）的操作說明；管理處人員亦可用手機模擬走一次以驗證 QR Code。

### 4.1 掃描 QR Code 開啟意見表單

1. 以手機相機／掃描應用程式掃描屋苑張貼的 **QR Code**。
2. 系統自動開啟該屋苑的「**客戶意見反饋**」表單（網址帶有屋苑代碼，例如 `?estate=CWC`）。
3. 頁面頂部顯示屋苑名稱（例如「灣景中心」），右上角可切換 **繁／EN**。

> 若掃描後出現「連結無效」或舊內容，請見第 11 章 FAQ。

（待補截圖：意見表單）

### 4.2 意見表單欄位說明

| 區塊／欄位 | 必填 | 說明與限制 |
|---|---|---|
| 意見種類 | 是 | 多選（**最多 3 項**）：管理處人員服務／保安人員服務／維修事宜／衞生事宜／滋擾事宜／其他；未選顯示「請至少選擇一項」 |
| 其他事項說明 | 選擇「其他」時 | 最多 **50 字**，輸入時顯示字數（如 `12/50`） |
| 稱謂 | 是 | 下拉：先生／女士／小姐／太太／不願透露 |
| 姓名 | 是 | 最多 **50 字** |
| 電郵 | 二擇一 | 格式須為電郵；**電郵或電話至少填寫一項**，方便管理處跟進 |
| 電話 | 二擇一 | 例如 `+852 9123 4567` |
| 事發日期 | 是 | 日期選擇器 |
| 事發時間 | 否 | 時間選擇器 |
| 地址（座／樓層／單位） | 否 | 選填 |
| 意見內容 | 是 | 多行輸入，最多 **1000 字**；輸入時顯示字數 |
| 願意接受後續滿意度調查 | 否 | 開關（預設**開啟**）；關閉後個案完結不會寄送問卷 |
| 私隱政策同意 | 是 | 必須勾選「我已閱讀並同意〔連結〕私隱政策」方可提交 |

操作提醒：

- 表單內容會**自動暫存**於瀏覽器（sessionStorage），不小心重整頁面可繼續填寫。
- 按「**重設**」會清空整份表單及暫存草稿。
- 提交按鈕：待命時顯示「**提交意見**」，送出中顯示「**提交中…**」。
- **重複提交保護**：同一聯絡資料與內容於 **10 分鐘內**重複提交時，系統不會建立新個案，會導向成功頁並顯示「閣下於 10 分鐘內已提交相同意見，此為原有個案編號：…」。
- 表單逾期（頁面停留過久）再提交，會顯示「表單已過期，請重新載入後再提交」，重新整理後重填即可。

### 4.3 提交成功頁

提交成功後顯示「**感謝您的反饋！**」成功頁，內容包括：

- 你的**個案編號**（淺藍底色方框），可按「複製」存起，日後查詢使用。
- 剛才選擇的意見種類與意見內容預覽、屋苑名稱。
- 按「返回」回到意見表單首頁。

> 請記下或複製個案編號；如日後需補充資料，可致電管理處並提供編號。

（待補截圖：成功頁）

### 4.4 滿意度問卷

個案審核通過並關閉時，系統會為**同意參與調查**的客戶建立匿名問卷連結，並按其於意見表單提供的聯絡方式送達。問卷以**匿名**方式進行，不紀錄個人資料。

| 項目 | 說明 |
|---|---|
| 開放時限 | 連結有效期由系統設定（預設 **14 天**，可由系統管理員於「參數」調整為 1–90 天） |
| 評分題 | **4 題**：整體滿意度／回應速度／服務態度／問題解決，每題 1–5 分（1 非常不滿意～5 非常滿意） |
| 開放意見 | 「其他意見（選填）」，最多 **2000 字** |
| 提交 | 全部 4 題評分後按「**提交問卷**」；未完成會提示「請為全部 4 題評分後再提交。」 |

提交完成後顯示「**感謝您的回覆！**」與「回覆編號、平均分」，意見將轉交屋苑服務處跟進。

**問卷連結失效的 3 種情況**（畫面會說明原因）：

| 顯示 | 意思 |
|---|---|
| 此問卷已過期 | 連結超過有效期限，恕無法重發；可直接聯絡屋苑服務處 |
| 此問卷已提交 | 已填寫過，重複提交不受理 |
| 問卷連結無效 | 連結不正確或找不到該問卷 |

> 隱私說明：問卷為匿名統計，後台只會顯示各題平均分與整體統計，不會顯示你的個人資料。

## 5. 個案處理（前線與客服）

### 5.1 個案狀態與顏色

| 狀態 | 中文標籤 | 顏色 | 意思 |
|---|---|---|---|
| PENDING | 待分派 | 灰 | 新提交，尚未分派處理人員 |
| ASSIGNED | 已分派 | 藍 | 已分派處理人員，尚未開始處理 |
| IN_PROGRESS | 處理中 | 橙 | 處理人員已開始處理 |
| WAITING | 待客戶回覆 | 紫 | 等候客戶補充資料／回覆 |
| RESOLVED | 已完結（待審核） | 青 | 已提交完結申請，等待主管／客服審核 |
| CLOSED | 已關閉 | 綠 | 審核通過，個案正式關閉 |
| REOPENED | 已重開 | 紅 | 因二次投訴或跟進不足而重開 |

### 5.2 個案列表（`個案` 頁）

#### 篩選與查詢
在頁面上方的篩選列設定條件後，按「**套用**」；按「**重設**」恢復預設。

| 篩選項目 | 說明 |
|---|---|
| 屋苑 | 下拉選擇；帳號只限單一屋苑時會被鎖定 |

### 5.4 動作區 — 個案各階段的操作

動作區的按鈕會依**目前狀態**與**你的權限**自動出現。常用流程：

```
待分派 ──分派──▶ 已分派 ──開始處理──▶ 處理中 ──申請完結──▶ 已完結（待審核）──審核通過並關閉──▶ 已關閉
  │                  │                    │                    └──駁回──▶ 返回處理
  └──轉派──▶ …     （等候客戶回覆 ⇄ 恢復處理）       （可於關閉後依需要重開）
```

各動作按鈕說明：

| 動作 | 按鈕文案 | 用途與輸入 | 需要權限 |
|---|---|---|---|
| 分派 | 分派 | 指派處理人員（可加優先級與分派說明）；未有處理人員的個案使用 | case:assign |
| 轉派 | 轉派 | 改派另一位處理人員，須填寫轉派原因（並可加補充說明） | case:assign |
| 開始處理 | 開始處理 | 確認開始跟進（可加備註），個案進入「處理中」 | case:update |
| 等候客戶回覆 | 等候客戶回覆 | 已聯絡客戶並等候回覆（可填等候原因），個案進入「待客戶回覆」 | case:update |
| 恢復處理 | 恢復處理 | 收到客戶回覆後恢復處理（可加備註） | case:update |
| 申請完結 | 申請完結 | 填寫**完結結果**與**處理內容摘要**（必填）等資料後送出審核 | case:resolve |
| 審核通過並關閉 | 審核通過並關閉 | 主管／客服審核完結申請；通過後個案關閉，系統會寄出感謝與問卷電郵（客戶同意時） | case:review |
| 駁回完結申請 | 駁回完結申請 | 完結申請不符合要求時駁回，須填寫**駁回原因**（必填） | case:review |
| 重開個案 | 重開個案 | 已關閉個案因二次投訴／跟進不足重開，須填寫**重開原因**並選取重開標記 | case:reopen |
| 跟進紀錄 | 跟進紀錄 | 在「已分派／處理中／待客戶回覆／已重開」狀態下記錄跟進內容（首筆由處理人員寫入時，會記為首次回應時間） | case:update |
| 變更優先級 | （優先級下拉） | 在上述四種狀態旁直接下拉變更高／中／低，即時生效 | case:update |

**完結結果選項**（申請完結時）：已徹底解決／部分解決／無法解決／客戶撤回投訴／已轉介其他部門。結果為「無法解決」時，須說明原因。另可填寫客戶回覆情況與完成日期。

**重開標記選項**：二次投訴／跟進不足。

> 小提醒：先寫「跟進紀錄」再「申請完結」，可讓時間軸完整呈現處理過程，有助審核。

### 5.5 附件

- 個案處理過程中的附件（例如住戶提供的相片、轉介文件）會集中顯示於個案詳情「**附件**」卡（顯示附件數量）。
- 支援格式 **jpg／jpeg／png／pdf**，單一檔案上限 **10MB**。
- 按附件名稱即可**下載**；系統會於處理時間軸記錄附件事件（例如「附件：檔案名稱」），**不可修改或刪除**。

### 5.6 SLA（服務水平）與逾期處理

系統按**事件類型**設定首次回應與關閉時限（預設值，可由系統管理員於「參數」調整）：

| 事件類型 | 首次回應時限（預設） | 關閉期限（預設） |
|---|---|---|
| 緊急（URGENT） | 5 分鐘 | 7 天 |
| 一般（NORMAL） | 30 分鐘 | 7 天 |
| 複雜（COMPLEX） | 120 分鐘 | 7 天 |
| 即時（INSTANT） | 240 分鐘 | 7 天 |

- **首次回應**：由處理人員寫入首筆跟進紀錄時自動記錄；遲了會觸發提醒／升級。
- **關閉期限**：由提交時間起計（預設 7 天）。
- 臨近期限或已逾期時，系統會於通知中心發出**提醒／升級**通知（由 SLA 掃描排程處理），個案列表會以淺紅底色標示「SLA 逾期」。
- 個案詳情「SLA 時限」卡顯示各項期限與實際時間，逾期顯示紅色「已逾期」。

### 5.7 二次投訴

## 7. QR Code 管理（`QR Code` 頁）

> 需要權限：查閱＝QR Code 查閱（預設 ADMIN、客服中心主管）；**生成／停用／重新生成**＝QR Code 生成／停用（預設僅 **ADMIN**）。

QR Code 管理頁以**每屋苑一列**的方式管理 4 個屋苑的 QR Code。表格欄位：**屋苑（中文名＋代碼＋英文名）｜狀態｜QR Code（縮圖）｜掃描連結內容｜生成日期｜有效日期｜操作**。

### 7.1 設定表單網站網址（僅 ADMIN）

QR Code 的掃描連結為「**表單網站網址 ＋ `?estate=屋苑代碼`」**。

1. 在「表單網站網址」設定卡（附「僅管理員」標籤）輸入網址，格式須以 `http://` 或 `https://` 開頭（例如 `https://feedback.example.com`）。
2. 按「**儲存設定**」，成功會顯示「表單網址設定已儲存」。
3. 卡片下方會顯示「**目前 QR 指向：{網址}**」供確認。

> 若**留空**：系統會以「目前訪問後台的網址」作為表單網址。本機測試時會指向 `localhost`，系統會把指向 localhost／127.0.0.1 的啟用碼標示為「過期（舊連結）」並自動作廢，正式環境請務必設定正式網址。

（待補截圖：QR Code 管理頁）

### 7.2 生成 QR Code

| 目前狀態 | 操作 |
|---|---|
| 未生成 | 該列顯示「**生成 QR**」按鈕；按後生成並顯示縮圖 |
| 已生成 | 可下載或停用（見 7.3） |

注意：系統**每屋苑只會有一個「啟用」的 QR Code**。按「**重新生成**」產生新碼時，同屋苑其他啟用碼會被自動停用，確保張貼與掃描的永遠是單一有效碼。

生成後建議：按「**PNG**／**SVG**」下載並以手機實際掃描測試，確認開啟的是正確屋苑的意見表單。

### 7.3 下載與停用／啟用

| 動作 | 位置 | 說明 |
|---|---|---|
| 下載 PNG | 操作欄 PNG | 下載點陣圖檔，適合列印 |
| 下載 SVG | 操作欄 SVG | 下載向量圖檔，適合放大印刷／製作標貼 |
| 停用 | 操作欄（僅啟用時顯示） | 讓現行 QR Code 失效（掃描不再導向表單）；會彈出確認對話框 |
| 啟用 | 操作欄（僅停用時顯示） | 重新啟用已停用的碼 |
| 重新生成 | 操作欄 | 產生全新 QR Code（自動停用同苑其他啟用碼） |

每個動作執行前都會彈出**確認對話框**，避免誤操作；所有動作均記錄於審計日誌。

### 7.4 QR Code 狀態標籤

| 狀態 | 顏色 | 意思 |
|---|---|---|
| 啟用 | 綠 | QR Code 有效，掃描可正常提交意見 |
| 停用 | 灰 | 已被停用（人工停用或重新生成時自動停用） |
| 未生成 | 橙 | 尚未產生 QR Code |
| 已過期 | 紅 | 已逾「有效日期」，由系統自動停用 |
| 過期（舊連結） | 橙 | QR 內容仍指向已失效的舊連結（如 localhost），視為不可用 |

### 7.5 有效日期與自動到期

「有效日期」欄位可為每個屋苑的 QR Code設定「自動到期」機制。

**原則**

- **預設空白＝永遠有效（不會自動停用）**。
- 設定日期後，該 QR Code 會**持續有效至該日香港時間 23:59:59**；逾期後由系統**自動停用**，狀態變為「**已過期**」。

**操作步驟**

1. 在該列「有效日期」欄的日期選擇器揀選日期（`YYYY-MM-DD`）。
2. 按「**儲存**」，成功後畫面顯示「已設為 {日期}」（或清空時顯示「已改為永遠有效」）。
3. 若要改為永遠有效：清空日期輸入框再按「儲存」即可。
4. 若要讓「已過期」的碼重新可用：先清空有效日期並儲存，再按「**啟用**」。

> 自動到期由系統定時掃描執行（測試環境約每 1 分鐘一次，可於部署時調整），即使沒人開啟後台亦會自動停用；因此「已過期」狀態的顯示可能稍有延遲。
> 用途舉例：短期活動（如屋苑節、維修通告）張貼的 QR Code，可預先設定到期日，活動結束後自動失效，毋須人手處理。

### 7.6 注意事項

- QR Code 是住戶提交意見的唯一入口，**停用／重新生成前請確認**已張貼的新碼可用。
- 更換表單網站網址後，現有啟用碼的「掃描連結內容」欄會隨之反映；若新網址與舊碼指向不同（例如由 localhost 改為正式網址），系統會把舊的死碼標示為「過期（舊連結）」。
- 每屋苑只保留一組啟用碼；重新生成前的舊碼會自動停用。

| 操作 | 步驟與說明 |
|---|---|
| 新增用戶 | 填寫**登入帳號**（建立後不可改）、姓名、Email、電話、所屬屋苑（全屋苑 ALL／各屋苑）、**角色（可多選，介面提示「角色決定該用戶的權限集合」）**。初始密碼可自行輸入；留空則系統自動產生**一次性密碼**，該使用者首次登入須更改密碼 |
| 修改 | 修改姓名、Email、電話、屋苑、角色等；帳號不可修改 |
| 重設密碼 | 系統產生一次性密碼並以視窗顯示，須交予使用者首登改密 |
| 鎖定／解鎖 | 帳號連續登入失敗被鎖定，或需暫停使用者登入時鎖定；解除後即可再登入 |
| 停用／啟用 | 停用（軟刪除）後該帳號無法登入但資料保留；可隨時重新啟用 |

存檔成功會顯示「已新增／已更新用戶」提示。

> 建置建議：每個員工使用獨立帳號、各配最少的必要角色；離職或調職時即時停用或調整權限。

### 10.2 角色與權限（`角色` 頁）

管理角色及其權限。列表欄位：**角色代碼｜名稱｜數據範圍（全屋苑／單屋苑）｜權限數｜用戶數｜狀態｜操作**。

| 操作 | 說明 |
|---|---|
| 新增角色 | 按「新增角色」建立新角色 |
| 修改 | 編輯名稱、數據範圍（全屋苑 ALL／單屋苑 ESTATE）；**權限**以「權限綁定」方式依「模組 × 操作」分組勾選（個案、參數、QR Code、用戶、角色、審計、屋苑、儀表板等模組） |
| 複製 | 以現有角色的權限為範本，另建新角色（加快設定） |
| 停用／啟用 | 停用後該角色下的使用者將無法再使用其權限 |

> 注意：修改角色的權限會**即時影響**該角色下所有使用者的可用功能；修改前請確認不會令現有員工失去必要功能。

### 10.3 操作審計（`審計` 頁）

完整記錄所有重要操作，作為責任追蹤與稽核依據。頁面底部標示「日誌不可竄改，保留 1 年」。

- **篩選**：操作類型（下拉：登入／登出／建案／分派／狀態變更／重開／參數變更／匯出／QR 產生、停用、啟用／用戶管理／角色管理／屋苑管理／週報／問卷等）、操作人（文字）、日期「起／迄」，再按「**查詢**」。
- **欄位**：時間｜操作人｜操作｜目標｜明細。操作以標籤色塊顯示；目標格式如「targetType#targetId」；明細為 JSON 內容。
- 審計日誌**不可修改或刪除**，只可查閱。

### 10.4 系統參數（`參數` 頁）

> 需要權限：查閱＝參數查閱；**編輯＝僅系統管理員**。

頁面按參數分組以卡片顯示，每列顯示**中文名稱＋參數鍵、目前值、最近更新人與時間**。頁面頂部會顯示目前模式：

- 「**可編輯模式（修改即時生效＋完整審計）**」：你有編輯權限，參數列旁會顯示「**編輯**」按鈕。
- 「**唯讀檢視（config:view）**」：只有查閱權限；唯讀列會標示「僅 ADMIN 可編輯」或「唯讀」。

**可編輯參數一覽**（預設值，正式環境可能已調整）：

| 分組 | 參數鍵 | 名稱 | 說明／預設 |
|---|---|---|---|
| SLA 時限 | sla.response | 首次回應時限（分鐘） | 依事件類型：緊急 5／一般 30／複雜 120／即時 240 分鐘 |
| SLA 時限 | sla.closure_days | 關閉期限（天） | 個案須於 N 天內關閉（預設 7，可設 1–30） |
| SLA 時限 | sla.reminder | SLA 提醒提前量 | 各事件類型提前提醒分鐘數＋關閉期限提前天數 |
| 意見種類對應 | category.event_mapping | 意見種類 → 事件類型對應 | 例如維修事宜 → 即時（INSTANT） |
| 問卷 | survey.expiry_days | 問卷調查有效期（天） | 預設 **14**，可設 1–90 |
| 週報 | weekly_report.schedule | 週報自動產生排程 | 星期＋時間（預設星期一 09:00） |
| 表單樣式 | form.style | 公眾表單樣式 | 主色（預設 #1a5aa6）、中文／英文標語 |

**唯讀／其他系統參數**（僅顯示，由系統維護）：問卷題目（survey.questions）、密碼有效天數（pwd.max_age_days，預設 90）、個案編號規則（numbering）、表單種類與欄位定義、QR Code 指向之表單網址（form.site_base_url，於「QR Code 管理」頁設定）等。

**修改參數的方法**

1. 在可編輯參數列按「**編輯**」。
2. 於對話框輸入新值後按「**儲存**」。
3. 儲存後**即時生效**，並寫入「更新紀錄」（變更審計，保留最近 50 筆），系統會通知系統管理員與客服中心主管。

> 說明：目前實作為「管理員直接修改、即時生效」模式（功能規格書中的「建議 → 審批」兩段式流程暫未啟用，系統預留了變更審計供日後追蹤）。修改 SLA 或問卷有效期等會影響日常運作的參數前，請先與相關主管確認。

### 10.5 屋苑管理（`屋苑` 頁）

> 需要權限：查閱＝**屋苑查閱（estate:list）**；新增／修改／停用＝**僅系統管理員（estate:manage）**。無 `estate:list` 的角色進入頁面會顯示無權限提示。

屋苑主檔集中於此頁維護（列表欄位：**代碼｜中文名稱｜英文名稱｜公司｜狀態｜操作**）。操作後**不需重啟服務或修改程式**，各頁面的屋苑下拉與名稱顯示會自動生效。

| 操作 | 步驟與說明 |
|---|---|
| 新增屋苑 | 按「**新增屋苑**」，填寫：**屋苑代碼**（大寫英數、2–10 字、首字須為英文字母，建立後不可改，例：HHD）、**中文名稱**、**英文名稱**、**公司代碼**（例：CRPM／PML／SMS；決定個案編號的公司前綴） |
| 修改 | 修改中文／英文名稱或公司代碼。名稱修改後**即時反映**在個案列表、儀表板、問卷統計、QR Code 管理與用戶管理等處（名稱均由主檔帶出） |
| 停用／啟用 | 屋苑**只能停用、不能刪除**（既有個案與 QR Code 以主檔參照）。停用後：住戶掃描該屋苑 QR Code 提交意見會顯示「屋苑不存在」；「QR Code」頁不再列示該屋苑。重新啟用後即恢復受理（原本仍啟用之 QR Code 會直接恢復可用；已停用或已過期者請到「QR Code」頁重新生成） |

**新增屋苑後，建議依序處理：**

1. 於「**QR Code**」頁為新屋苑**生成 QR Code** 並下載張貼（見第 7.2 節）。
2. 於「**用戶**」頁為新屋苑開設「物業管理處主管／物業前線」等帳號（所屬屋苑選新屋苑，見第 10.1 節）。
3. 若設有週報排程，確認該屋苑主管帳號建立後即可收到所屬屋苑的週報。

> 所有新增／修改／停用動作均寫入「審計」日誌（操作類型：**屋苑管理**）。

## 11. 常見問題（FAQ）

### 11.1 掃描 QR Code 沒有反應，或開不到意見表單
- 確認以**相機／可掃碼的應用程式**對準 QR Code，並保持網絡連線。
- 請管理處人員在後台「QR Code 管理」查看該屋苑的狀態與「掃描連結內容」：
  - 「**未生成**」→ 尚未建立 QR Code，需要生成。
  - 「**已過期／過期（舊連結）**」→ 指向已失效的連結，需重新生成或改設有效日期後再啟用。
- 可先在後台以「**PNG／SVG**」重新下載並實際掃描測試。

### 11.2 QR Code 顯示「已過期」
代表該碼已超過所設「**有效日期**」，系統已自動停用。處理方法：於「有效日期」欄把日期**清空**（＝永遠有效）或改為未來日期，按「儲存」後再按「**啟用**」。

### 11.3 提交意見後沒記下個案編號
個案編號只顯示於提交成功頁一次。可致電管理處／屋苑服務處，提供姓名、聯絡方式、提交時間與意見內容以供查詢；管理處人員可在後台以關鍵字搜尋。

### 11.4 表單顯示「表單已過期」或「重複提交」
- 「表單已過期，請重新載入後再提交」→ 頁面停留過久，**重新整理**後重填即可。
- 「閣下於 10 分鐘內已提交相同意見…」→ 同一內容於短時間內重複送出，系統不會重複建案；請以原有個案編號跟進。

### 11.5 問卷連結顯示「已過期／已提交／無效」
見第 4.4 節的三種情況。問卷**無法重發或重填**；如有需要請直接聯絡屋苑服務處。

### 11.6 不記得密碼
聯絡系統管理員執行「**重設密碼**」（第 10.1 節）。重設後系統會提供一次性密碼，首次登入時必須更改。

### 11.7 帳號被鎖定
連續多次登入失敗會自動鎖定帳號。請聯絡系統管理員按「**解鎖**」；如非本人操作，請同時考慮重設密碼。

### 11.8 登入後看不到某個功能或按鈕
你的角色沒有該權限（見第 2.2 節）。後台只顯示有權限的頁面與按鈕，這是正常設計；如工作需要，請向系統管理員申請調整角色或權限。

### 11.9 附件無法上傳
系統只接受 **jpg／jpeg／png／pdf**，且**單一檔案不超過 10MB**。請檢查格式與大小後重試。

### 11.10 想補充或撤回已提交的意見
系統不提供網上修改／撤回功能。請記下個案編號並聯絡管理處／屋苑服務處；處理人員可在個案詳情記錄跟進，或在必要時提出「駁回／重開」等流程。

### 11.11 不想收到滿意度問卷
提交意見表單時，關閉「**願意接受後續滿意度調查**」開關即可（此開關預設開啟）。若已提交但想取消參與調查，請聯絡管理處／屋苑服務處協助安排。

### 11.12 「空白＝永遠有效」是什麼意思
指 QR Code「有效日期」欄留空時，該 QR Code **不會自動到期停用**，會一直有效，直至管理員人工停用。此為預設行為。

### 11.13 更換表單網站網址後，舊 QR Code 是否仍然有效
QR Code 的「掃描連結內容」會隨新網址更新；但若舊碼掃出的是已失效的舊網址（例如本機 localhost），系統會把舊碼標示為「**過期（舊連結）**」並停用。請以「重新生成」建立新碼並重新張貼。

### 11.14 問卷統計看不到個別住戶的回覆
滿意度問卷是**匿名**設計，後台「問卷統計」只顯示整體與各屋苑的統計，不會亦無法顯示個別個人資料。

### 11.15 操作到一半顯示「未登入」或「登入已過期」
工作階段逾時。請重新登入；未儲存的輸入會遺失，建議完成重要操作前先儲存。

### 11.16 如何新增／修改／停用屋苑
新增屋苑不需修改程式。系統管理員於後台「**屋苑**」頁按「新增屋苑」填寫代碼、中英文名稱與公司代碼即可；修改名稱、停用／啟用亦於同一頁操作。詳見第 10.5 節。新增後記得為新屋苑生成 QR Code 並開設所屬屋苑帳號。

## 12. 附錄

### 12.1 常用選項字典

**意見種類**：管理處人員服務（MO_SERVICE）／保安人員服務（SECURITY）／維修事宜（MAINTENANCE）／衞生事宜（CLEANLINESS）／滋擾事宜（NUISANCE）／其他（OTHER）

**事件類型**：緊急（URGENT）／一般（NORMAL）／複雜（COMPLEX）／即時（INSTANT）／不適用（N/A）

**優先級**：高（HIGH）／中（MEDIUM）／低（LOW）

**完結結果**：已徹底解決／部分解決／無法解決／客戶撤回投訴／已轉介其他部門

**重開標記**：二次投訴／跟進不足

**稱謂**：先生／女士／小姐／太太／不願透露

**個案管道**：QR／CC／SITE／APP／EMAIL（見第 6.3 節）

### 12.2 名詞對照

| 名詞 | 意思 |
|---|---|
| 個案 | 一宗住戶意見／投訴，由提交起至關閉止由系統全程追蹤 |

| 首應期限 | SLA 規定的首次回應最後時限 |
