## 2. 角色、權限與數據範圍（RBAC 三層）

權限由「模組 × 操作 × 數據範圍」三層描述，儲存於 `sys_permission(perm_code, module, perm_name, perm_type)`。

### 2.1 權限碼（本期啟用）

| 權限碼 | 模組 | 說明 | 綁定角色 |
| --- | --- | --- | --- |
| `user:list` | user | 用戶列表/查閱 | ADMIN, CC_SUPERVISOR, ESTATE_SUPERVISOR |
| `user:create` | user | 新增用戶 | ADMIN |
| `user:update` | user | 修改用戶（含角色/屋苑/鎖定） | ADMIN, CC_SUPERVISOR, ESTATE_SUPERVISOR |
| `user:disable` | user | 停用/啟用（軟刪） | ADMIN |
| `user:reset_pwd` | user | 重設為一次性密碼 | ADMIN |
| `user:lock` | user | 鎖定/解鎖 | ADMIN |
| `role:list` | role | 角色查閱 | ADMIN, CC_SUPERVISOR, ESTATE_SUPERVISOR |
| `role:manage` | role | 角色新增/修改/停用/複製 | ADMIN |
| `audit:view` | audit | 審計查閱 | ADMIN, CC_SUPERVISOR, ESTATE_SUPERVISOR, AUDITOR |
| `user:list`, `audit:view` 已於種子；其餘由 `db/ensureDefaults.js` 冪等補綁（既有 DB 亦生效） |

### 2.2 權限矩陣（對照規格書 §5.10）

| 操作 | ADMIN | CC_SUPERVISOR | CC_STAFF | ESTATE_SUPERVISOR | ESTATE_STAFF | AUDITOR |
| --- | --- | --- | --- | --- | --- | --- |
| 用戶列表 | ● | ◐ | — | ◐ | — | — |
| 用戶新增/修改/停用/重設/鎖定 | ● | — | — | — | — | — |
| 角色查閱/管理 | ● | ◐(查) | — | ◐(查) | — | — |
| 審計查閱 | ● | ● | — | ◐ | — | ● |

> ● 完整 ｜ ◐ 部分（列表/查閱，不含寫入）｜ — 無
> 說明：CC_SUPERVISOR / ESTATE_SUPERVISOR 具 `user:list`/`role:list`/`audit:view`，符合「◐」；寫入類權限（`user:create`/`disable`/`reset_pwd`/`lock`/`role:manage`）僅 ADMIN。

### 2.3 數據範圍

- 用戶建立時須指定所屬屋苑 `estate_code`（其值為 `ALL` 表示全屋苑）；列表依操作人範圍過濾：`ALL` 看全部，單屋苑僅看同屋苑。
- 角色 `data_scope`：`ALL`（跨屋苑）或 `ESTATE`（限定所屬屋苑）。

## 3. 資料模型（F-010 相關，節錄）

```sql
-- 用戶（關鍵欄位）
sys_user (
  user_id INTEGER PK, username TEXT UNIQUE, password_hash TEXT,
  full_name TEXT, email TEXT, phone TEXT, estate_code TEXT,
  security_question TEXT, security_answer_hash TEXT,
  must_change_pwd INTEGER DEFAULT 0,   -- 強制改密旗標（首登/管理員重設）
  is_active INTEGER DEFAULT 1,         -- 停用軟刪
  failed_attempts INTEGER DEFAULT 0,  -- 連續錯誤計數
  locked_until TEXT,                   -- 鎖定到期（ISO+08:00）
  pwd_changed_at TEXT,                 -- 密碼最後變更（過期判斷）
  last_login_at TEXT, created_at TEXT, updated_at TEXT
);

-- 角色 / 權限 / 關聯（已存在）
sys_role (role_id, role_code UNIQUE, role_name, data_scope, is_active);
sys_permission (permission_id, perm_code UNIQUE, module, perm_name, perm_type, is_active);
sys_user_role (user_id, role_id);          -- 用戶↔角色（多對多）
sys_role_permission (role_id, permission_id); -- 角色↔權限（多對多）

-- 操作審計（append-only；FR-010-05 / 規格書 7.3.6）
audit_log (
  audit_id INTEGER PK, user_id INTEGER, username TEXT,
  action TEXT,            -- LOGIN/USER_MANAGE/ROLE_MANAGE/CONFIG_CHANGE/...
  target_type TEXT, target_id TEXT, detail TEXT(JSON),
  ip TEXT, user_agent TEXT, created_at TEXT
);
```

密碼：bcrypt（`bcryptjs`，cost 10，種子帳號 cost 6）。令牌：JWT（`jsonwebtoken`，含 `userId/estateCode/roles/permissions`）。

## 4. 後端 API 契約（掛載於 `/api/v1`）

> 統一信封：`{ status:'ok', data, message? }` / `{ status:'error', code, message, lang }`（見 `src/middlewares/error.js`）。
> 全部需 `Authorization: Bearer <token>`；權限不足回 `2005/403`；未帶 token 回 `2001/401`。

### 4.1 變更密碼（FR-010-04）

`POST /api/v1/auth/change-password` ｜ requireAuth

```jsonc
Request:  { "currentPassword": "string|optional", "newPassword": "string" }
Response: { "changed": true }
```
- 新密碼強度：`≥8` 位且同時含英文大寫、小寫、數字（`utils/password.isStrong`）。
- 非強制改密情境（用戶 `must_change_pwd=0`）須提供 `currentPassword` 且比對正確；缺則 `400`，錯誤則 `2002/401`。
- 成功：寫入 `password_hash`、`pwd_changed_at=now`、`must_change_pwd=0`、`failed_attempts=0`、`locked_until=NULL`，並寫 `audit_log(action=USER_MANAGE, op=change_password)`。

### 4.2 用戶管理（FR-010-01/02/04/05/06）

| Method | Path | 權限 | 說明 |
| --- | --- | --- | --- |
| GET | `/users?keyword=&estate=&role=&active=&sortBy=&sortDir=&page=&pageSize=` | `user:list` | 列表（依操作人數據範圍過濾） |
| POST | `/users` | `user:create` | 新增（不給 `password` 則產生一次性密碼＋`must_change_pwd=1`） |
| PUT | `/users/:id` | `user:update` | 修改資料/角色/屋苑/安全問題（不含密碼） |
| DELETE | `/users/:id` | `user:disable` | 停用（軟刪，`is_active=0`） |
| POST | `/users/:id/reset-password` | `user:reset_pwd` | 重設為一次性密碼，回傳 `tempPassword` |
| POST | `/users/:id/lock` | `user:update` | 鎖定 30 分（`locked_until=now+30m`, `failed_attempts=5`） |
| POST | `/users/:id/unlock` | `user:update` | 解鎖（清 `locked_until`/`failed_attempts`） |

新增 Request 欄位：`username`(3~50 英數._-)、`fullName`、`email?`、`phone?`、`estateCode`(須存在或 `ALL`)、`roles[]`(角色碼)、`password?`、`securityQuestion?`、`securityAnswer?`。
防呆：停用最後一位啟用中 `ADMIN` 回 `2005/409`（不可停用最後一位管理員）。

### 4.3 角色管理（FR-010-03/07）

| Method | Path | 權限 | 說明 |
| --- | --- | --- | --- |
| GET | `/roles` | `role:list` | 角色列表（含權限碼/用戶數）＋全量權限目錄 `permissions[]` |
| POST | `/roles` | `role:manage` | 新增角色（含 `permissions[]` 綁定） |
| PUT | `/roles/:code` | `role:manage` | 修改名稱/數據範圍/權限/啟用 |
| POST | `/roles/copy` | `role:manage` | 複製角色（FR-010-07：`{fromRoleCode, roleCode, roleName}`） |
| DELETE | `/roles/:code` | `role:manage` | 停用（軟刪，`is_active=0`） |

角色碼格式：`^[A-Z][A-Z0-9_]{1,29}$`（如 `ESTATE_MANAGER`）。權限碼須存在且啟用。

### 4.4 操作審計查閱（FR-010-05）

`GET /api/v1/audit?action=&username=&targetType=&from=&to=&page=&pageSize=` ｜ `audit:view`
- 過濾：`action`(白名單)、`username`(LIKE)、`targetType`、`from`/`to`(時間範圍)。
- 回傳：`{ total, page, pageSize, items[], actions[] }`；`detail` 為 JSON 物件。
- 日誌 append-only，本端點僅查閱，不提供刪除/修改；保留 1 年（規格書 7.3.6）。

### 4.5 錯誤碼新增

| code | HTTP | 說明 | 對應規格書 8.5 |
| --- | --- | --- | --- |
| `2006` | `401` | 必須先變更密碼後方能繼續（首登/管理員重設後；或密碼超過 `pwd.max_age_days` 預設 90 天） | 2006 |

## 6. 密碼策略（FR-010-04，落地規則）

| 規則 | 實作 |
| --- | --- |
| 強度 | `≥8` 位，含大寫＋小寫＋數字（`utils/password.isStrong`）；重設產生 12 位一次性密碼 |
| 90 天更換 | 登入時若 `pwd_changed_at` 距今 ＞ `pwd.max_age_days`（config 預設 90）則回 `2006` 強制改密（初始 `null` 不視為過期，避免示範帳號被鎖） |
| 5 次錯誤鎖 30 分 | 沿用既有登入鎖定邏輯（`failed_attempts`/`locked_until`），`/users/:id/lock` 可手動鎖定 |
| 首登強制改密 | 管理員代建不給密碼 → `must_change_pwd=1`；登入即回 `2006` |

## 7. 審計（FR-010-05，落地）

- 用戶/角色之新增、修改、停用、重設密碼、鎖定/解鎖、改密，皆經 `utils/audit.writeAudit` 寫入 `audit_log`，`action` 分別為 `USER_MANAGE` / `ROLE_MANAGE`，`detail` 記錄操作類型與對象。
- `audit_log` 無更新/刪除介面，確保不可竄改；保留 1 年（建議後續排程歸檔，本期不實作）。

## 8. 測試與驗收路徑（可運行骨架）

### 8.1 後端測試

- 檔案：`backend/test/rbac.test.js`（Node 內建 `node --test` + `supertest`，不依賴 jest）。
- 覆蓋：權限閘道（401/403）、用戶新增/強制改密標記、改密成功後可登入、密碼強度拒絕、重設密碼回傳一次性密碼、防呆（最後管理員不可停用）、角色新增/修改/複製/停用、審計寫入與查閱、權限不足者不可查閱審計。
- 執行（於 `backend/` 目錄）：`npm test` 或 `node --test test/rbac.test.js`，**全綠（18/18）**。
  > 註：登入端點有 60s/5 次速率限制，測試僅於檔頭登入 admin 與 chng_staff 各一次共用 token。

### 8.2 前端驗收

1. `backend/` 啟動（`npm start`，自動建表＋種子＋`ensureDefaults`）。
2. `frontend/` 啟動（`npm run dev`），瀏覽 `http://localhost:5173`。
3. 以 `admin / Admin@2026` 登入 → 個案列表頂部「用戶 / 角色 / 審計」導覽。
4. 用戶頁：新增用戶（留空密碼）→ 該用戶首登被導向改密；重設密碼對話框顯示一次性密碼。
5. 角色頁：新增/修改角色並勾選權限；複製既有角色。
6. 審計頁：切換操作類型/操作人查詢，確認用戶與角色操作均被記錄。
