## 產品概述

在現有「QRCode 客戶意見反饋系統」後台新增「QR Code 管理」功能頁，讓管理員按屋苑生成 QR Code 貼紙，住戶掃描後直接進入該屋苑的「客戶意見反饋」表單提交意見。

## 核心功能

- 後台入口：登入後從頂欄進入「QR Code 管理」頁（具 `qr:view` 權限者可見）。
- 屋苑 QR 一覽：列出全部屋苑（灣景中心/攸壆路/頌雅苑/大夫第）及其現行 QR：狀態（啟用/停用/未生成）、QR 預覽圖、生成日期、指向的內容連結。
- 生成與重新生成：按屋苑生成新 QR（內容為表單 URL + `estate` 參數），新碼啟用時自動停用該屋苑舊碼並記錄停用時間；每次生成寫入 `qr_code` 表與審計日誌。
- 停用/啟用切換：可停用現行 QR（失效貼紙）或重新啟用，保證每屋苑同時只有一張啟用碼。
- 下載：每張 QR 提供 PNG（列印高解析度，可選尺寸）與 SVG 兩種格式下載。
- 表單網址設定：頁面頂部可設定表單網站主機（`form.site_base_url`），未填時自動退回「目前訪問後台的網址」構成 QR 內容；QR 內容只帶 `estate` 參數，不帶語言，表單依手機瀏覽器語言自動顯示繁中/英文。
- 權限：QR 查閱與圖片為 `qr:view`；生成/停用/網址設定為 `qr:generate`（僅 ADMIN，客服中心主管可查閱）。

## 視覺效果

延續現有後台風格（淺灰背景、白色圓角卡片、黏性頂欄），以一張屋苑 QR 表格呈現每苑狀態、預覽與操作按鈕，操作直觀、可列印。

## 技術棧

- 沿用現有架構：Express 4 + better-sqlite3（後端）、React + TypeScript + MUI（前端）、SQLite 既有 `qr_code` / `sys_config` / `audit_log` / `sys_permission` 表。
- 新增依賴：`qrcode`（npm，支援 PNG buffer 與 SVG 字串輸出，產生 1024px 高解析度 PNG 約數十毫秒，無需落盤儲存檔案）。

## 實作方案

### 整體策略

1. 後端新增 `qr` 路由與服務層（對齊 `cases.js` + `caseService` 模式）：查詢總覽、生成、停用/啟用、即時輸出 PNG/SVG、儲存 site_base_url。所有變更寫 `audit_log`（沿用 `routes/cases.js` 的 INSERT 模式）。
2. 資料層補充（`ensureDefaults`，於 `initDatabase()` 中執行，相容已 seed 的現有 DB 不需重置）：補插 `qr:generate` 權限碼並綁定 ADMIN；CC_SUPERVISOR 補綁 `qr:view`；插入 `form.site_base_url`（空字串）設定；將種子資料中指向 `localhost` 的過期 QR 記錄標為停用（`is_active=0` + `invalidated_at`）。
3. QR 圖像不落盤、由 API 即時產生（PNG/SVG），`file_url` 存該圖像 API 路徑；前端預覽與下載皆指向 `/api/v1/qr/:qrId/image`，避免靜態檔管理與清理負擔。
4. QR 內容構成：`base = site_base_url.trim() || 目前請求 protocol://host`，內容為 `${base}/?estate=${屋苑代碼}`（不帶 lang，自動偵測語言）；URL 一律由後端白名單核對屋苑代碼後組裝。
5. 前端新增 `QrCodePage`（沿用 CaseListPage 的頁面骨架與視覺）並於 `App.tsx` 註冊 `/admin/qr`（AuthGuard）；在個案列表頁頂欄加「QR Code 管理」入口（依 `qr:view` 權限顯示），QR 頁提供返回列表。

### 效能與可靠性

- 每屋苑保證單一啟用碼：生成/啟用時以單一 UPDATE 停用同屋苑其他碼，避免多碼並存造成貼紙混亂。
- 總覽查詢對 `sys_estate` LEFT JOIN 子查詢（每屋苑最新啟用碼），屋苑僅 4 個，無效能瓶頸。
- 圖像產生加 `Cache-Control: private, max-age=3600`；縮圖請求帶小 size 參數，降低負載。
- `site_base_url` 以正則 `^https?://` 驗證並 trim，防注入非法協定。

### 避免技術債

- 完全沿用既有 `ok(res,data)`/`ApiError`/`requireAuth`+`requirePerm`/`getConfig` 模式；不引入新框架或新架構。
- 資料遷移採冪等 `INSERT OR IGNORE`/有條件 UPDATE，任何環境重啟皆安全。

## 實作筆記

- 錯誤碼：在 `constants.js` 新增 `QR_NOT_FOUND: 1005` 並於 `i18n.js` 補繁中/英文訊息，供 QR 404 使用；權限不足沿用 `ERR.PERMISSION`。
- 審計動作命名沿用大寫風格：`QR_GENERATE`、`QR_DEACTIVATE`、`QR_REACTIVATE`、`QR_CONFIG`，`target_type='QR'`、`target_id=qr_id 或 estate_code`，detail 存 JSON。
- 前端下載沿用 `downloadExport` 的 blob 模式，檔名如 `QR_CHNG.png` / `QR_CHNG.svg`。
- 影像 API 需註冊於 `app.js` 的 SPA fallback 之前（與 `/api` 前綴規則一致，天然滿足）。
- seed 不再預插 qr_code 死碼（新裝庫由管理員首次生成）；舊庫由 `ensureDefaults` 作廢 localhost 碼，UI 顯示「未生成」後引導生成。

## 架構設計

數據流：

- 管理員生成 → POST /api/v1/qr/generate → 停用舊碼 → 以 site_base_url（或 fallback host）組 URL → 插入 qr_code 記錄 → 寫 audit_log → 前端刷新總覽顯示新碼。
- 住戶掃碼 → GET {site}/?estate=CHNG → FormPage 載入表單（語言自動偵測，提交走既有 F-001 流程，不受本功能影響）。
- 下載/預覽 → GET /api/v1/qr/:qrId/image?format=png|svg&size=… → qrcode 即時產生。

## 關鍵介面契約

- `GET /api/v1/qr/overview`（qr:view）→ `{ siteBaseUrl, items: [{ estateCode, estateNameZh, estateNameEn, qrId|null, qrContent|null, active|null, generatedAt|null }] }`（每屋苑一行）。
- `POST /api/v1/qr/generate`（qr:generate）body `{ estateCode }` → 停用同苑舊碼、插入新碼、回傳新記錄；audit `QR_GENERATE`。
- `POST /api/v1/qr/:qrId/status`（qr:generate）body `{ active: boolean }` → 停用（或啟用並停用同苑其他碼）；audit `QR_DEACTIVATE`/`QR_REACTIVATE`。
- `GET /api/v1/qr/:qrId/image?format=png|svg&size=128..2048`（qr:view）→ 即時產生圖像；format 預設 png、size 預設 1024；qrId 不存在回 404（QR_NOT_FOUND）。
- `PUT /api/v1/qr/site-url`（qr:generate）body `{ siteBaseUrl }` → 驗證 https?://、空字串允許（清除）；audit `QR_CONFIG`。

## 設計風格

延續現有後台一致風格（不另創新視覺語言）：淺灰藍背景 #f4f6fa、白色圓角卡片（border-radius 8、1px #e5eaf2 邊框、細陰影）、黏性白色頂欄，整體專業冷靜的管理工具調性。

## 頁面規劃（1 頁：QR Code 管理）

- 頂欄（sticky）：左側「返回個案列表」連結與頁面標題「QR Code 管理」，右側顯示用戶與登出按鈕（與個案列表頁一致）。
- 區塊一「表單網站網址設定」卡片：說明文字（留空＝使用目前訪問網址）、單行 TextField、儲存按鈕；儲存後出現成功提示，並顯示目前 QR 指向的實際網址供列印前確認。
- 區塊二「屋苑 QR Code」表格卡片：表頭 屋苑 | 狀態 | QR 預覽 | 內容 | 生成日期 | 操作；每行含 128px QR 縮圖與下方可複製的內容連結、狀態標籤（啟用綠／停用灰／未生成橙）、操作按鈕（下載 PNG、下載 SVG、停用／啟用、重新生成）；未生成屋苑顯示主按鈕「生成 QR」；重新生成與停用彈出確認對話框防誤觸。
- 載入中與錯誤態沿用個案列表頁模式（spinner／Alert）；操作權限不足時隱藏生成類按鈕只留檢視。
